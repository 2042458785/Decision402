# Decision402 V1.0 — ETHGlobalTokyo2026 黑客松版本

记录日期：2026-10-03。[English](V1.0.en)

本文记录当前代码的业务流程，不包含后续改进计划。范围是 `cmd/decision402` 启动的网页 Agent；独立 CLI 演示不在这条流程里。

- 代码基线：[`403638b`](https://github.com/2042458785/Decision402/commit/403638be173ee99f633d332948b5cf882360ec5c)。检查时 HEAD 为 `3a3c31c`，相比基线只新增了计划文档，业务代码未变。
- 运行方式：本机 Go 服务＋Vue 页面；付款仅支持 Base Sepolia 测试 USDC。
- 当前用途：从四个本地收费接口中选择一个，购买固定的东京 23°C 天气样例。不是实时天气或公开服务市场。
- 本文按源码核对；此次没有重新执行真实 API 调用或测试网付款。`V1.0` 是版本名称，不代表已达到生产标准。

## 一句话流程

**连接钱包 → 创建 Agent → 充值测试币 → 设置任务和规则 → 读取报价 → 筛查地址 → 按规则选商家 → 预览或付款 → 展示记录。**

## 实际执行顺序

1. **连接钱包。** 页面连接 MetaMask，切到 Base Sepolia，用户签署登录消息；后台核验签名并建立会话。登录签名不转账。
2. **创建 Agent。** 用户填写名称和 DeepSeek 配置；后台生成独立 Agent 钱包，保存它与登录钱包的归属关系。钱包私钥和个人模型 Key 保存在本机，文件权限为 `0600`。
3. **准备付款资金。** 用户通过 MetaMask 向 Agent 钱包转入测试 USDC。只有 `pay` 需要付款资金，模拟和预览不转账。
4. **提交任务。** 用户设置指令、模式、单笔上限、任务上限和选择偏好。后台检查权限与参数，保存任务后执行。同一任务 ID、相同内容返回原任务；同 ID 改内容被拒绝。
5. **模型调用工具。** DeepSeek 理解指令，调用 `find_services`，再调用 `execute_purchase`。目前工具只支持东京样例。商家选择和付款由 Go 代码决定，模型不能改收款人或预算。
6. **读取报价、检查风险。** 后台检查 A/B/C/D。真实模式读取本地接口的 HTTP 402 报价，核对链、币种、金额、收款人和授权参数，再用 Intercepta 查询报价里的收款地址；同一轮相同地址共用扫描结果。
7. **筛选并排序。** 排除报价无效、风险未知、高风险、超过授权风险或预算的候选。价格优先：先比价格，再比风险；风险优先：先比风险，再比价格。没有候选就停止。
8. **按模式执行。** 模拟／预览展示选择结果后结束。付款模式重新请求选中商家，签名前核对报价未变、重新扫描地址并检查规则；先把“已预留一次付款尝试”写入磁盘，再由 Agent 钱包签署 x402 授权。卖方通过外部 facilitator 验证和结算，返回响应。
9. **保存并展示。** 应用先读取 `PAYMENT-RESPONSE` 结算头，再检查 HTTP 状态和 JSON。保存任务、筛选原因、付款结果和交易哈希；页面轮询显示这些记录。

## 三种模式

| 模式 | 报价和风险 | 付款 |
|---|---|---|
| `simulate` | 固定模拟值：A/B 风险 2、C 风险 1、D 风险 0 | 不签名、不付款 |
| `preview` | 真实读取本地 HTTP 402 报价，真实调用 Intercepta | 不签名、不付款 |
| `pay` | 与预览相同，签名前再次核对报价和风险 | 尝试一次测试网付款 |

三种模式都会调用 DeepSeek，可能产生模型费用。网页当前都要求先创建 Agent；网页的 `preview`／`pay` 只提交风险上限 0，风险上限 1 仅在模拟界面开放。后台规则本身支持 0 和 1。

## 四家演示商家

| 商家 | 价格（测试 USDC） | 收款地址配置 |
|---|---|---|
| A | 0.005 | 风险样例地址 |
| B | 0.02 | 与 A 相同的风险样例地址 |
| C | 0.01 | 单独配置的低风险样例地址；未配置时使用 D 的地址 |
| D | 0.05 | 预期正常的样例地址 |

以上风险名称只是配置用途。真实风险以接口返回及项目规则为准；0/1/2 是项目定义的等级，不是 Intercepta 官方风险分级。未发现风险不代表绝对安全。

## 出错后怎么处理

- **签名前失败：** 停止，状态通常为 `held`；不会自动再选一家付款。
- **已签名、结算不明：** 状态为 `unknown`，不自动重试。
- **结算头确认成功、数据读取失败：** 仍记录为 `settled`，另附数据错误；不会再付一次。
- **付款已预留但未确认结算：** 阻止整个服务的新付款，需人工核对。
- **服务重启：** 原先排队／运行中的任务转为 `held`，不会自动续跑。任务全局串行执行。

## V1.0 的边界

- 每个任务最多一次付款尝试；单笔与任务上限均不超过 0.10 测试 USDC，没有每日或跨任务累计账本。
- 能在首次筛选时避开不合格商家；尚未实现选定后失败自动换商家、自动查账恢复。
- 应用根据结算响应头记录付款，没有自行通过链上查询核验；数据只检查状态、大小和 JSON 格式，没有业务质量验收。
- 本地私钥未加密，不适合作为公开多用户资金保管服务；也没有 Arc 主网支持。
- 依赖 DeepSeek、Intercepta，以及卖方使用的 `https://x402.org/facilitator`。模拟模式也不是完全离线。
