# 钱包：现状与改进计划

[English](Wallet.en.md)

核对日期：2026-10-03。本文记录 Decision402 钱包相关部分（登录、创建 Agent、充值、付款签名）的现状，以及自研的改进方向。

## 现在钱包是怎么做的

一句话：**连 MetaMask 证明身份 → 创建 Agent 时后端生成新私钥存盘 → 用户用 MetaMask 直接转 USDC 充值 → 付款时后端用磁盘里的私钥替 Agent 签名。**

### 关键文件和位置

| 内容 | 位置 | 权限 / 是否加密 |
|---|---|---|
| Agent 钱包私钥 | `artifacts/agents/<id>.key` | 0600，明文 hex，未加密 |
| Agent 元数据（owner、钱包地址、DeepSeek key） | `artifacts/agents/<id>.json` | 0600，明文 |
| 默认付款私钥（无 Agent 时用） | `.buyer-key` | 明文 |
| 演示卖家私钥 | `.seller-key` | 明文 |
| DeepSeek + Intercepta key | `.env` | 明文 |

### 每个环节谁在做什么

| 环节 | 谁操作 | 说明 |
|---|---|---|
| 登录 | 用户 MetaMask 签名消息 | 只证明身份，不转账 |
| 创建 Agent | 后端生成 ECDSA 私钥写盘 | 私钥由后端持有 |
| 充值 | 用户 MetaMask 直接转 USDC 到 Agent 地址 | 平台不碰充值 |
| 查余额 | 前端 `eth_call` 读 USDC 合约 `balanceOf` | 链上读，平台不存 |
| 列出 Agent | `GET /api/agents` 按 owner 过滤 | 已有 |
| 付款签名 | 后端读 `.key`，用私钥签 x402 授权 | 用户不参与签名 |

## 现在的问题

### 密钥保管（最严重）

1. 私钥明文落盘（`.key`），只靠 0600 文件权限，没加密；能读到文件内容就能控制钱包。
2. DeepSeek API Key 明文存在 `.json`。
3. `.buyer-key`、`.seller-key`、`.env` 都是明文。
4. 没有口令，没有“锁定/解锁”。

### 控制权：谁的钱、谁签名

5. 付款由后端替 Agent 签名，用户的 MetaMask 只是登录身份，不是控制者。
6. Agent 钱包只有“充值”和“付款”，没有“转出/提现”；用户不能把里面的钱转回自己。
7. 私钥绑定在服务器磁盘，不在链上，用户无法证明“只有我能控制”。

### 托管与恢复

8. 中心化托管：私钥在平台，不是用户自托管，也不是智能账户。
9. 机器没了或文件被删，钱包永久丢失，没有恢复机制。
10. 有 `.lock` 文件锁，只能单实例跑，不支持多人/多实例。

### 额度

11. 只有单笔、单任务上限，没有每日累计和地址白名单；规则由后端内存判断，不在链上、不可验证。

### 次要

12. 登录 session 存在内存，服务重启就失效；1 小时过期。
13. 余额是前端实时 `eth_call` 读的，后端没有资产记录或历史。

## 预计要加的点（学 Circle，自研）

### 第一阶段：安全止血（先做）

1. 用 [go-ethereum keystore](https://github.com/ethereum/go-ethereum/tree/master/accounts/keystore) 把私钥从明文改成“口令加密”文件；口令由用户输入，平台不保存。
2. DeepSeek API Key 改成加密存储，或只放环境变量，不再明文进 `.json`。
3. 加“锁定/解锁”：锁定状态拒绝签名；签名时短暂解密到内存、用完清空。
4. 备份与恢复：导出加密 keystore，用口令恢复，并有测试验证。
5. 日志、接口响应、前端页面永不出现私钥、口令或 API Key。

### 第二阶段：用户控制（学 Circle “Agent 拿不到份额”）

6. Agent 钱包改成智能账户（ERC-4337 / 智能钱包）；用户用 MetaMask 签一次“授权”，限定：收款地址白名单 + 单笔/每日额度 + 有效期。
7. AI 在授权范围内自动签名，用户随时可撤销；后端不再持有完整私钥。
8. 加“转出/提现”：用户授权下把 Agent 钱包余额转回自己地址。

### 第三阶段：链上可验证 + 体验

9. 额度（单笔/日/周 + 地址白名单）上链或可链上验证。
10. 后端统一返回“Agent 列表 + 余额”，替换前端自己 `eth_call` 的零散查询。
11. 重连自动加载 Agent 和余额（已有，保持并完善）。

### 每项怎么算完成

- 错误口令、锁定后、用户 A 操作用户 B 的 Agent，都不能签名或付款。
- 备份能恢复；日志和响应无敏感信息。
- 付款不再由后端用明文私钥签；用户能看到并撤销授权。

## 与 Circle 的对照（学什么）

| Circle 的做法 | 我们怎么学 |
|---|---|
| MPC 2-of-2，Agent 拿不到份额 | 第一版不自研 MPC，用“智能账户 + 会话密钥”达到类似效果：用户保留控制、Agent 拿不到完整私钥 |
| 额度：单笔≤日≤周≤月 + 地址白名单 | 第一版先做“单笔 + 每日 + 白名单”，周/月再补 |
| 用户保留 custody | 目标：用户 MetaMask 能控制/撤销 Agent 钱包 |
