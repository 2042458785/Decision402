# 钱包改进：第一、二阶段

[English](Wallet.en.md) · 2026-10-05

## 第一阶段：普通 Agent 钱包的本地加密

| 功能 | 第一阶段之前 | 现在怎么做 | 有什么用 |
|---|---|---|---|
| 钱包私钥 | 私钥明文存在 `.key` 文件里；拿到文件内容的人就能使用钱包。 | 第一阶段创建普通 Agent 时生成一把完整私钥；用你的口令加密，放进 Agent 的 `.json`。不保存明文私钥文件或口令。 | 只复制 Agent 文件，不能直接花钱包里的钱。 |
| DeepSeek API Key | 个人 Key 明文存在 Agent 的 `.json` 文件里。 | 你填的个人 Key 用同一个口令单独加密，放进 Agent 的 `.json`；不填时可使用服务器配置的共用 Key。 | 看得到 Agent 文件的人，不能直接读出你的个人 Key。 |
| 锁定／解锁 | 登录后没有单独的钱包锁，也不需要再输入钱包口令。 | Agent 默认锁定。输入口令后，后台在当前登录会话中获得最多 10 分钟的临时使用权；手动锁定、退出、到期或重启后失效。 | 登录页面不等于一直允许付款。 |
| 签名与模型调用 | 付款时从明文 `.key` 文件读取私钥；调用模型时读取明文的个人 Key。 | 付款签名时，私钥短暂以明文出现在后台内存；调用 DeepSeek 时，个人 Key 也会短暂出现在内存。用完尽力清理。 | 不把明文私钥长期放在文件或内存里。 |
| 备份／恢复 | 没有供用户下载和导入的加密钱包备份。 | 下载的 keystore 只备份加密后的 Agent 钱包私钥。用它和原口令，可在创建 Agent 时导入同一个钱包地址；名称、个人 DeepSeek Key 要重新填写。 | 换电脑后还能使用原钱包里的钱；备份不是整个 Agent 或任务记录。 |
| 页面、接口和日志 | 普通接口已只返回公开钱包信息，但个人 Key 明文存在本地文件中；模型回复没有针对 Key 回显的拦截。 | 输入框遮住口令和 Key，操作后清空；普通接口和日志不输出明文密钥；模型若把正在使用的 API Key 回显，程序丢弃该回答。 | 减少不小心把秘密展示出去的机会。 |

文件怎么产生：MetaMask 登录不生成 Agent 文件。创建 Agent 后，项目电脑上出现 `artifacts/agents/<Agent ID>.json`：名称、钱包地址、模型设置是可读信息，私钥和个人 DeepSeek Key 是密文。提交任务后，另生成 `artifacts/tasks/<任务 ID>.json`，记录指令、预算、商家与报价、执行和付款结果。只有你点下载备份，浏览器才得到 `decision402-<Agent ID>.keystore.json`；它只备份钱包私钥，不含模型 Key 和任务。

10 分钟内存里发生什么：解锁时，后台短暂用口令解开文件里的私钥和个人 DeepSeek Key，随后用新生成的随机密钥把它们重新加密在内存里。口令不会作为 10 分钟凭证保存。十分钟内，后台需要签名或调用模型时，才临时从内存中取出相应明文，用完尽力清理。后台这段时间确实能使用这两样秘密；Go 无法保证清掉运行库留下的每一个内存副本。

加密说白了：口令可以把密文解回原文，不是“残缺私钥拼完整”。磁盘上的钱包私钥和个人 DeepSeek Key 都用 go-ethereum V3 的加密方法，分别加密，用同一个口令。具体是用 scrypt 从口令算出密钥，再用 AES-128-CTR 加密，并校验口令／密文；不是 AES-256。10 分钟的内存临时加密另用随机密钥和 AES-GCM。

目前的边界：加密文件仍保存在运行项目的电脑上，后台解锁时也会接触明文。它减少了文件被直接复制后的风险，但还不能当作成熟的多人资金托管服务。

## 第二阶段：用户控制付款

| 功能 | 第一阶段之后怎样 | 改了什么 | 为什么改 | 实际用处 |
|---|---|---|---|---|
| 钱包主控权 | 旧 Agent 是普通钱包；即使私钥已加密，后台解锁后仍可用完整私钥签名。MetaMask 负责登录和充值，不能撤销 Agent 的私钥。 | 新 Agent 使用 ERC-1271 智能钱包：MetaMask 控制合约，后台只保存加密的受限签名钥匙。 | 限制后台解锁后能做的事。 | 即使受限钥匙泄露，也不能绕过合约直接提走智能钱包的 USDC。 |
| 授权范围 | 只有应用检查每个任务的预算和风险；链上没有用户给 Agent 的收款白名单与期限。 | 用户用 MetaMask 发授权交易，写入收款白名单、单笔／每日额度和有效期。首次部署是另一笔交易。 | 把花钱边界交给钱包合约检查。 | 用户设好范围后，Agent 可在范围内自动买数据，不用每笔都找人签。 |
| 跨任务额度 | 每个任务检查自己的额度，多个任务不会合起来算每日花费。 | 每笔付款先在链上占用额度；同一个智能钱包的任务共用当天额度，重新授权也不会清零。 | 防止拆成多个任务后超支。 | 例如日限额 0.20 USDC，已有两笔各占 0.10，第三笔会被拒绝。 |
| 付款签名 | 本地检查通过后，普通钱包直接签 x402 付款。 | 链上先记录这笔付款的金额、收款人等信息，再由受限钥匙签名；合约只认已占额度的那笔签名。 | 防止只靠后台规则约束受限钥匙。 | 后台即使出错，也不能让该钥匙给白名单外地址签出有效付款。每笔多一笔链上交易。 |
| 撤销 | 本地锁定只能阻止新签名，已签出的付款仍可能结算。 | 用户用 MetaMask 发 `Revoke onchain`；交易上链后，旧授权下尚未结算的签名失效。 | 用户需要从链上收回授权。 | 发现异常时可以停掉后续付款；已经完成的转账无法撤回。 |
| 转出／提现 | 页面没有把 Agent 余额转回用户的操作。 | `Withdraw with MetaMask` 只能由主控发起，USDC 只能转回主控地址。 | 停用 Agent 时不能把余额困在钱包里。 | 用户结束试用后可取回剩余测试 USDC；受限钥匙不能提现。 |
| 后台停机 | 撤销和提现若只靠项目页面，后台故障时会影响用户操作。 | 可保存独立控制页 `wallet-control.html` 和合约地址，用 MetaMask 直接撤销、提现。 | 用户控制权不能依赖后台一直在线。 | 项目程序停了，仍能管理已部署的钱包。 |
| 备份含义 | 第一阶段的 keystore 备份的是旧普通钱包的完整私钥。 | 新智能钱包的 keystore 只备份受限钥匙；恢复后要重新绑定原合约地址。 | 两种钥匙的权限不同。 | 换电脑可继续使用 Agent；MetaMask 主控钱包要单独备份。 |

**先分清两把钥匙。** 第一阶段的钱包只有一把完整私钥：后台解锁后，能用它控制钱包。第二阶段把钱放在链上的智能钱包里。你的 MetaMask 是主控；项目后台保存的是另一把加密的“受限钥匙”。它只能按你写进合约的规则付款，不能改规则或提现。

**你先设规则。** 创建 Agent 时生成受限钥匙。你用 MetaMask 部署智能钱包，把测试 USDC 转进去，再授权：能付给哪些地址、每笔最多多少、一天最多多少、授权到什么时候。部署和授权都需要你分别在 MetaMask 确认。受限钥匙地址还需要一点测试 ETH，用来支付每次占额度的链上手续费。

**Agent 买一次数据。** 项目先检查报价、风险和任务预算。选定商家后，受限钥匙先向合约登记“准备给这个地址付多少钱”，占用当天额度；这一步要上链。然后它才签 x402 付款。商家结算时，合约只认可这笔已登记、仍在授权范围内的签名。**占额度不等于钱已经付出**；即使购买失败，当天占过的额度也不会退回。

**你想停下或取钱。** `Lock now` 只停本地新签名；`Revoke onchain` 要用 MetaMask 发交易，上链后才会让旧授权失效；`Withdraw with MetaMask` 把合约里剩下的 USDC 转回你的 MetaMask 地址。受限钥匙即使泄露，也不能直接提现，但在撤销上链前仍可能按已有规则购买。

**换电脑时备份什么。** Agent 的 `.json` 记着智能钱包合约地址、加密的受限钥匙和加密的个人 DeepSeek Key。下载的 keystore **只备份受限钥匙**，不备份合约里的钱，也不备份 MetaMask。恢复时需要原口令、原智能钱包合约地址和原 MetaMask 主控钱包；个人 DeepSeek Key 要重新填写。

## 现在怎么操作

| 场景 | 做法 |
|---|---|
| 新 Agent | MetaMask 准备 Base Sepolia 测试 ETH → `Create agent + session key` → `Deploy with MetaMask` → `Fund with MetaMask` 给合约充测试 USDC → `Fund session gas` 给受限钥匙地址充少量测试 ETH → `Authorize with MetaMask` 设置白名单、限额和有效期 → 解锁后运行任务。部署和授权是两笔交易；每笔购买还要上链占额度。 |
| 换电脑 | 保存加密 keystore、口令及智能钱包合约地址。恢复时选对钱包类型；智能钱包还要绑定原合约地址。备份文件不含个人 DeepSeek Key。 |
| 暂停或退出 | `Lock now` 停止本地新签名；`Revoke onchain` 在交易上链后作废链上授权；`Withdraw with MetaMask` 把智能钱包余额转回自己。 |

## 仍需知道

| 情况 | 事实 |
|---|---|
| “永不泄露” | 口令和 Key 输入时会短暂经过页面与后台内存；Go 不能保证擦掉运行库的所有副本。不要把其他秘密写进任务文本，因为任务文本会保存。 |
| 每日额度和手续费 | 按 UTC 零点重置（北京时间 08:00）。付款未成功，已占的额度当天也不退；跨日后，前一天尚未结算的签名失效。受限钥匙地址可花自己的 ETH，只给它少量手续费。 |
| 付款结果不明 | 占额度的交易哈希先保存，USDC 付款签名前另记一笔。USDC 付款结果未知时，现有程序仍会挡住后续付款，避免重复付。部署超时也要先查交易，成功后绑定原合约，别重复部署。 |
| 能力范围 | 当前是 ERC-1271 智能钱包，没有实现完整 ERC-4337。旧普通钱包仍由后台保管加密私钥；新钱包的受限钥匙也保存在后台。 |
| 验证范围 | 已有合约、本地 x402 扣款、Go 并发和模拟 MetaMask 页面测试。尚未在公共 Base Sepolia 用真实 MetaMask 与公共 facilitator 跑完整付款，也未做独立合约审计。 |
