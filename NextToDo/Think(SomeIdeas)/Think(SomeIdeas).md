# 接下来怎么做，哪些想法值得试

更新：2026-10-03。[English](<Think(SomeIdeas).en.md>)

## 先定方向

**先把一条真实购买流程做稳，再增加复杂功能。** 钱包、预算、付款和选商家由我们自己做；Circle 用来学习，不接它的托管服务。

- 五个部分是：用户定规则、找服务、按规则选商家、查风险、执行付款。现状见 [V1.0](<../Version/V1.0(ETHGlobalTokyo2026Hackathon)/V1.0.md>)，具体任务见 [HowToImprove](../HowToImprove/HowToImprove.md)。
- 先在现有 Go 项目里分清各部分的职责，不急着拆成多个服务。每改一部分，都要保证整条购买流程还能运行。
- 除了五个部分，还要做好钱包保管、累计账本、异常恢复和数据检查。Interceptor 只是风险检查的一部分，不能代表整个产品；风险数据来源以后可以更换。
- 比较 Circle 时只问四件事：我们现在怎么做、它提供什么、我们缺什么、改完怎么检查。它已有制裁筛查，不能把“有风险拦截”当作我们的独有优势。
- 复杂创新可以晚点做，但要先找到真实任务。基础功能做全，不代表用户就会需要。

## 可以试的五件事

前两项跟主计划一起做；后三项等购买流程稳定后再选。

| 想法 | 怎么做 | 怎么判断有用 |
|---|---|---|
| 完善现有预览 | 显示商家、价格、风险和选择原因，不签名付款 | 两位开发者能看懂，也愿意继续试 |
| 写清购买结果 | 显示买了什么、花多少、数据是否合格、为什么失败 | 用户不需要找我们解释失败记录 |
| 让其他 Agent 调用 | 提供一个接口，接收任务并返回数据和花费；只能在已有授权内操作 | 一位开发者能接进自己的项目 |
| 记录商家表现 | 先记录成功、过期、价格和耗时；积累记录后再调整选择 | 记录能解释问题，调整后确实有改善 |
| 公开演示收反馈 | 展示实际能力；反馈记下任务、问题和重现方法 | 有真实任务反馈，也有人回来继续用 |

## 什么时候该调整

- 两天内找不到两家用途和支付方式都合适的服务：先换用途，不先做大市场。
- 固定一家就够用：先做好预算和付款恢复，暂缓复杂 AI 选择。
- 现有产品已够用：问用户还缺什么，再决定继续做哪部分。

**目前的把握：** 代码缺什么已有依据；上面的产品想法仍需试用。优先验证能否减少失败、人工处理和无效花费，不先承诺商业成功。
